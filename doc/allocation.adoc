[#lexical-allocation]
== Allocation

A validator and a rule allocate nothing, but the IRI functions, which allocate
only through a memory resource, where the table below says:

[%header,cols="3,5"]
|===
| Function or rule | Allocates
| every validator and rule but those below | never: Boost.URL's views and lexical's rules hold no storage, idna works in fixed storage, a `range_rule` keeps its rule inline, and `is_regex` reads its pattern in place (<<lexical-regex-allocation>>)
| `is_iri`, `is_iri_reference`, `iri_rule`, `iri_reference_rule` | never for an ASCII IRI or one whose mapped URI fits 1,024 octets; beyond, one buffer of the mapped length, from the resource given, else `std::pmr::get_default_resource()`
|===

A test counts every call of the global `operator new` its program makes,
over every validator and rule, on long and hostile inputs, a megabyte of
each format among them, and finds none but those the table names, on every
target.

The stack holds the rest: an IRI's buffer of 1,024 octets, idna's working
storage of a label, and the descent of `is_regex` into a pattern's groups,
which `max_regex_nesting` bounds (<<lexical-regex-bounds>>).
