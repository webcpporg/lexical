[#formats-identifiers]
== Identifiers

`is_uuid` checks RFC 9562's string form of a UUID: 32 hexadecimal digits in
either case, in groups of 8, 4, 4, 4 and 12 joined by hyphens. It checks the
shape, not the version or the variant, as JSON Schema's suite asks; braces
and the `urn:uuid:` prefix are not part of the form.

`is_json_pointer` checks RFC 6901's JSON Pointer: the empty string, or
reference tokens each led by `/`, in which `~` is followed by `0` or `1`. A
token holds any other code point, NUL included, so the string is decoded as
UTF-8 and must be well-formed.

`is_relative_json_pointer` checks a relative JSON Pointer: a non-negative
integer without a leading zero, then `#` or a JSON Pointer. Draft 2020-12 and
v1 of JSON Schema cite draft-bhutton-relative-json-pointer-00, which lets an
index manipulation follow the integer, a sign and a positive integer (`0+1`,
`1-1#`); drafts 7 and 2019-09 cite draft-handrews-relative-json-pointer-01,
which has none. The function takes that choice as its second argument:
`index_manipulation::allowed`, the default, for 2020-12 and v1, and
`index_manipulation::refused` for 7 and 2019-09. The rule takes it as
`relative_json_pointer_rule_t{index_manipulation::refused}`. A sign that no
positive integer follows (`0+`, `0+0`, `0-01`) is no manipulation, under
either choice.
